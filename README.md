# 承認フロー基盤(approval-flow-kit)

業種を設定ファイルで切り替える、多段承認フローのデモアプリです。

承認フローの骨格、つまり「誰が・どの順で・何を確認して承認するか」は、業種が変わってもほとんど同じ形をしています。
違うのは中身だけです。そこで骨格をエンジンに、中身を `templates/*.json` に分けました。
**業種を増やす作業は、JSONを1枚書くことに閉じます。** アプリのコードには業種名が1つも出てきません。

同梱している5業種は、すべて同じ `app.js` が動かしています。

| テンプレート | 申請するもの | 分岐の条件 |
|---|---|---|
| `recruiting` | 人材紹介 / 推薦文 | 送付種別、企業担当の確認の要否 |
| `construction` | 建設 / 施工計画書 | 請負金額、高所・重機作業の有無 |
| `manufacturing` | 製造 / 設計変更申請 | 安全・法規への影響、客先支給図の変更 |
| `care` | 介護 / ケアプラン | 医療的ケアの有無、区分変更の有無 |
| `agency` | 広告 / 入稿クリエイティブ | 商材カテゴリ、No.1表示の有無 |

## 動かし方

```bash
npm install
npm start
# http://localhost:3000/
```

環境変数なしで動きます。Slackの設定も不要です(通知は `/inbox/demo` に溜まります)。

| URL | 内容 |
|---|---|

## テンプレートの書き方

`templates/` に JSON を1枚足すだけで、新しい業種が画面に現れます。再起動は必要です。

```json
{
  "id": "legal",
  "name": "士業 / 提出書類の承認",
  "summary": "画面の説明文に出ます",
  "terms": {
    "request": "提出書類",     
    "subject": "案件名",
    "counterparty": "提出先",
    "body": "書類の要旨"
  },
  "fields": [
    { "key": "deadline", "label": "提出期限", "type": "text", "required": true },
    { "key": "kind", "label": "種別", "type": "select", "options": ["登記", "申告"], "required": true }
  ],
  "checks": [
    { "type": "needNumber", "msg": "日付や金額が入っていません" }
  ],
  "routes": [
    { "name": "申告", "when": [["kind", "==", "申告"]], "steps": ["担当", "有資格者", "所長"] },
    { "name": "通常", "when": [], "steps": ["担当", "所長"] }
  ],
  "roles": ["担当", "有資格者", "所長"]
}
```

### checks(形式チェック)で使える種類

| 種類 | 設定 | 何を見るか |
|---|---|---|
| `sentences` | `min` `max` | 文の数 |
| `sentenceLen` | `max` | 1文の長さ |
| `minLen` / `maxLen` | `n` | 全体の字数(空白を除く) |
| `needNumber` | なし | 数字が1つでも入っているか |
| `needWords` | `words` `any` | 必須語。`any:true` ならどれか1つ、`false` なら全部 |
| `banWords` | `words` | 禁止語。引っかかった語を画面に出します |
| `maxWordCount` | `words` `n` | 指定した語の合計出現回数の上限 |

`msg` は必須です。**引っかかったときに何を直せばよいかが書かれていない指摘は、運用では無視されます。**

### routes(承認ルート)の判定

上から順に見て、`when` の条件をすべて満たした最初の行を採用します。`when` が空の行がフォールバックなので、必ず最後に置いてください。

使える演算子は `==` `!=` `>=` `<=` `>` `<` `contains` `empty` `notEmpty` です。
左辺には `fields` のキーのほか、`subject` `counterparty` `body` `bodyLen`(本文の字数)が使えます。

判定結果には、必ず理由を添えて画面に出します。「請負金額が 5000 以上」のような文です。
**ルートだけ出しても、運用では「なんでこの人が入るの?」で必ず止まる**ためです。

## 設計上の判断

**形式チェックと承認ルートの実装は1つだけにしています。**
画面側でも同じ判定をしたくなりますが、書くとサーバー側と二重管理になり、必ず片方だけ直されてズレます。
そこで画面は入力のたびに `POST /check/:secret` を叩き、サーバーの判定をそのまま表示しています。

**差し戻しは「否決」ではなく、ひとつ前の工程へ戻す逆リレーです。**
実務の差し戻しは、その大半が「直せば通る」ものです。止めて終わりにすると、直したものを流す経路が別途必要になります。
先頭まで戻ると申請者の手元に返り、そこで取り下げるか、直して再申請するかを選びます。

**差し戻しには理由を必須にしています。**
理由のない差し戻しは、受け取った側が何を直せばよいか分かりません。空のまま送ると400で止めます。

**承認者は個人ではなく役割に紐づけています。**
テンプレートが書くのは役割名だけで、人名は書きません。人は入れ替わりますが、役割はあまり変わらないためです。

**外部通信は落ちてもフローを止めません。**
Slack通知は try-catch で包み、送ろうとした内容は必ず通知ボックスに残します。

## 公開して置くときの注意

保存先はコンテナ内のJSONファイルです。永続ディスクを持たない環境(Renderの無料プランなど)では、
スリープからの復帰や再デプロイのたびに初期状態へ戻ります。デモとしてはむしろ都合がよく、
誰が触ったあとでも常に同じ状態で見せられます。

ただし**起動時の業種も既定値に戻る**ため、最初に見せたい業種を `DEFAULT_TEMPLATE` で指定してください。
既定は `construction` です。

実案件で納品するときは、保存先をデータベースか永続ディスクに変える必要があります。

## 技術

- Node.js 18以上 / Express のみ。ビルド不要
- 単一ファイル(`app.js` 約700行)、保存は `data/*.json`
- `.env` を置けば起動時に読み込みます(環境変数側が優先)

## これは何のためのものか

人材紹介の推薦承認フローを作ったとき、業種固有だと思っていた部分の多くが、実は
「条件で承認者が変わる」「出す前に形式を機械で見る」「差し戻しを逆向きに流す」という共通の形に落ちることが分かりました。
その共通部分だけを取り出して、業種を設定で差し替えられるようにしたのがこれです。
